# to2610-gpu 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

一颗小的并行计算芯片，面向 ECOS 2610 班车。片上是 Adam Majmudar 的 tiny-gpu：四个核，每个核一次跑一个「块」的四个线程，十六个线程同时执行同一段内核程序，各自凭线程号去取、去算、去存自己的那一份数据。这是 GPU 的计算模型（SIMT）缩到最小的样子，用来做并行计算与最简单的渲染实验。

片上没有处理器。内核程序与数据由片外主机经 SPI 写进片上的两块存储，主机再设线程数、起跑，等 `done` 脚拉高后把结果读回去。主机可以是笔记本（USB 转 SPI），也可以是 `to2610-kvc` 那颗 Linux 片的 SPI 主口。

tiny-gpu 的源码一行不改，按上游的做法过一遍 sv2v；本仓加的是两块存储与管理口（`hwsrc/`）。转换出来的文件上只补一处：上游例化程序存储的控制器时有四个输入没接，这里接成 0（`htest/tieoff.py`，缘由见局限）。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 计算核 | 4 个 | 每核有自己的取指、译码、调度，四个线程各一套寄存器、ALU 与访存单元 |
| 每块线程数 | 4 | 一个核一次跑一块；块多于核时，哪个核先空出来就领下一块 |
| 线程数 | 4 至 252，取 4 的整数倍 | 上游在最后一块装不满时不结束，所以要是整数倍 |
| 指令 | 11 条，16 位 | `NOP`、`BRnzp`、`CMP`、`ADD`、`SUB`、`MUL`、`DIV`、`LDR`、`STR`、`CONST`、`RET` |
| 寄存器 | 每线程 13 个通用寄存器，8 位 | 另有三个只读的：`%blockIdx`、`%blockDim`、`%threadIdx`，线程凭它们算出自己是第几个 |
| 程序存储 | 256 条 | 片上触发器，所有线程共用，只读 |
| 数据存储 | 256 字节 | 片上触发器，所有线程共用；四路并发读写，多于四个线程同时访存时排队 |
| 管理口 | SPI 从口，模式 0 | SCK 不超过主频的八分之一，即 6.25 MHz；协议与 `to2610-switch`、`to2610-router` 的管理口相同 |
| 状态脚 | `done`、`busy` | 主机可以不轮询，直接等 `done` 脚 |
| 拍数计数 | 32 位 | 从起跑到结束的时钟拍数，用来比不同线程数、不同写法的快慢 |

### 一次计算的过程

1. 主机写程序存储与数据存储，写线程数。`sw/gpu.py` 装载时把数据存储整块写一遍，内核没给初值的字节是 0。
2. 主机往 `CTRL` 写 1。片上先给 tiny-gpu 两拍复位，再把线程数送进它的设备控制寄存器，然后拉高 `start`；`busy` 脚随之拉高。
3. 调度器把线程按四个一块分给空闲的核。每个线程从第 0 条指令跑到 `RET`，一条指令走取指、译码、取数、等存储、执行、写回六步。
4. 所有块跑完，`done` 脚拉高，`busy` 落下，拍数停住。
5. 主机读回数据存储。要再跑一遍：往 `CTRL` 写 0 再写 1；数据存储不清，上一遍的结果还在。

### 管理口协议

SPI 模式 0（CPOL 0、CPHA 0），高位先出，`CS_N` 低有效。地址与数据都是 4 字节大端，地址低 2 位不看。

| 命令 | 主机发 | 芯片回 |
|:--:|:--:|:--:|
| 0x02 写 | 4 字节地址，再每字 4 字节数据 | 无；每收满一字写一次，地址加 4 |
| 0x03 读一字 | 4 字节地址，1 个空字节 | 4 字节数据 |
| 0x0B 连读 n + 1 字 | 4 字节地址，1 字节 n，1 个空字节 | 每字 4 字节 |
| 0x05 状态 | 1 字节 | 第 0 位：访问过没有东西的地址。读一次即清 |
| 0x9F 标识 | 4 字节 | 53 50 49 53，即「SPIS」 |

这一颗的管理口是手写的 Verilog（`hwsrc/spi_regs.v`），不是 `spis` 那个 IP，协议照它做，所以主机端用同一份 `sw/spis.py`。

### 主机端工具

`sw/gpu.py` 里有三样：汇编器（内核的写法照 tiny-gpu 的说明，`.threads`、`.data` 加指令）、软件模型（照硬件实际的行为逐条执行）、经 SPI 的装载与起跑。整片测试也经它装载与读回，所以上板用的就是测过的那份。

| 命令 | 做什么 |
|:--:|:--:|
| ident | 读标识与配置，回核数与每块线程数 |
| emu 内核文件 | 只在本机跑软件模型，打出数据存储 |
| run 内核文件 | 汇编、装载、起跑、等结束、读回，打出拍数与数据存储，并与软件模型比 |

`sw/kernels/` 里有三个内核：

| 内核 | 线程 | 算什么 |
|:--:|:--:|:--:|
| `saxpy.asm` | 16 | y = 3x + y，一人一项 |
| `matmul.asm` | 16 | 4 × 4 矩阵乘，一人一个元素，线程里有循环 |
| `shade.asm` | 64 | 8 × 8 的灰度图，一人一个像素：到中心距离的平方 |

## 寄存器

都在 `0x1000_0000` 起的一页里，按字对齐。

| 地址 | 名字 | 读写 | 含义 |
|:--:|:--:|:--:|:--:|
| `0x1000_0000` | CTRL | 读写 | 第 0 位：写 1 起跑，写 0 收手 |
| `0x1000_0004` | THREADS | 读写 | 线程数，低 8 位 |
| `0x1000_0008` | STATUS | 只读 | 第 0 位 done，第 1 位 busy |
| `0x1000_000C` | CYCLES | 只读 | 从起跑到 done 的时钟拍数；下一次起跑时清零 |
| `0x1000_0010` | ID | 只读 | `0x5447_5055`，即「TGPU」 |
| `0x1000_0014` | CONFIG | 只读 | 第 15 至 8 位核数，第 7 至 0 位每块线程数 |
| `0x1000_0400` 起 256 字 | 程序存储 | 读写 | 每字低 16 位是一条指令 |
| `0x1000_0800` 起 256 字 | 数据存储 | 读写 | 每字低 8 位是一个字节 |

这一页里别的地址、这一页之外的地址，读写都回错，记在管理口的状态字里。

## 板级连接

| payload 位 | 方向 | 信号 | 接到 |
|:--:|:--:|:--:|:--:|
| 56、57、58 | 入 | SCK、CS_N、MOSI | 主机的 SPI 主口，模式 0 |
| 59 | 出 | MISO | 主机；只在 CS_N 为低时驱动 |
| 60 | 出 | done | 主机的一根输入脚，或一颗 LED |
| 61 | 出 | busy | 示波器、逻辑分析仪的触发，或一颗 LED |
| 其余 | — | 没用到 | 高阻，悬空即可 |

管理口的四根脚与 `to2610-switch`、`to2610-router` 在同一组位上，三颗共用一种管理排线。payload 第 n 位是 MPC-Frame 的 `user_io[n + 7]`。

- 时钟 50 MHz，与别的几颗用同一块底板。
- 主机：USB 转 SPI（FT232H）或树莓派的 spidev；SCK 不超过 6.25 MHz。
- 与 `to2610-kvc` 联动：Linux 片的 SPI1 主口接这里的管理口，`done` 接它的 GPIO，在 Linux 里装载内核、取回结果。
- 渲染结果的显示由主机做：读回数据存储里的那块图，在主机上画出来，或由主机再推给一块 SPI 屏。

## 测试说明

| 用例 | 验证什么 |
|:--:|:--:|
| management | 标识、配置、状态；两块存储各写满 256 个随机数再整块读回；写不进去的高位读回为 0，邻居不受牵连；这一页里外三处没有东西的地址都回错，状态字读一次就清 |
| saxpy | 十六个线程算 y = 3x + y，结果与算式、与软件模型都相同，x 没被动过；拍数在合理范围；不重装数据再起跑一遍，`done` 先落下，结果在上一遍之上又加了一次 |
| matmul | 4 × 4 矩阵乘，线程里有循环与条件跳转，结果与算式、与软件模型相同 |
| shade | 六十四个线程各算一个像素，十六个块轮流占四个核，结果与算式、与软件模型相同 |
| one_block | 线程数只有 4：只跑一个块，别的核没有动数据存储 |

全部用例跑在交付的那份 `.v` 上，经五口顶层进出；装载与读回走 `sw/` 里上板用的同一份代码。tiny-gpu 本身另在黑盒仓 `tiny-gpu` 里跑上游自带的两个测试（矩阵加、矩阵乘），核数与每块线程数各取几档。

## 局限

- 数据与寄存器都是 8 位，程序 256 条、数据 256 字节，这是 tiny-gpu 指令集定下的。能演示并行的做法，算不了实用的东西。
- 上游的比较只分得出相等与不等：`CMP` 之后「小于」那一位永远是 0，「大于」那一位在两数不等时为 1。所以 `BRn` 的实际效果是「不等则跳」，循环要写成数到相等为止。软件模型照这个行为写。
- 除以 0 的结果不定，内核里要自己避开。
- 线程之间没有同步手段，两个线程写同一个地址时谁后写谁留下，内核要让各线程写的地址不重叠。
- 没有处理器：内核靠主机装载，掉电即失。带向量扩展的主核没有放进这一版，见 `the-target/todo.md`。
- tiny-gpu 没有流过片（上游只把它的 ALU 送过 Tiny Tapeout），上游仓也没有许可文件；这里只挂子模块，不改也不转载它的源码。
- 上游有一处悬空的输入：程序存储的控制器例化时没接写的那一半，而控制器里照样在看它们。上游的仿真里悬空的输入是不定态、条件判断当它是假，所以不出事；综合之后它们是工具随手挑的常数。在交付的这份文件上，不补的话控制器的状态一复位就变成不定态，一条指令也取不出来——整片测试第一次跑就是这样卡住的。这里明写接 0。
